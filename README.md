# Jiro brand

The source of truth for the brand values shared by Jiro's public sites:
[new-website](https://github.com/jirozone/new-website) (www.jiroco.com),
[apply](https://github.com/jirozone/apply) and [portal](https://github.com/jirozone/portal).
The repo is public on purpose: everything in it ships to browsers anyway, and the apps' CI can read
it without a token.

## What's here

- `tokens.json`: the brand font, the base corner radius and the colour tokens every site shares, named after the shadcn
  roles all three use (`primary`, `muted-foreground`, …). Colours are HSL channels (`"240 100% 9%"`),
  which every app (all on Tailwind 4) declares as `hsl(240 100% 9%)`.
- `assets/`: the logo and every icon, generated by `npm run generate` (`scripts/generate-assets.mjs`)
  from the font's own outlines, so no file depends on an installed font or a browser:
  - `wordmark.svg` / `wordmark-white.svg`: "Jiro" in bold (700), cropped to the ink.
    `wordmark.json` holds the same path for inline components (`fill="currentColor"`, height
    `heightEm` × the font size of the text it replaces).
  - `mark.svg`: white "J" on a full-bleed navy square, the app icon.
  - `favicon.svg`, `favicon.ico`, `favicon-16.png`, `favicon-32.png`: the mark on a rounded square
    for browser tabs.
  - `apple-touch-icon.png`, `icon-192.png`, `icon-512.png`: full-bleed mark for home screens; iOS
    and Android round the corners themselves.
  - `og-image.png`: the 1200×630 link preview.

App-specific tokens stay in each app: portal's credit-score risk scale and sidebar, the website's
hero colours.

`success` (`160 84% 33%`) is dark enough for white icons on it and for large text or icons on the
page background (3:1). It is not dark enough for body text (4.5:1).

## How the apps use it

Each app commits a copy at `brand/tokens.json` and has:

- a unit test that fails if its stylesheet's `:root` drifts from the copy
- `node scripts/sync-brand.mjs` to refresh the copy from this repo's `main`, and
  `node scripts/sync-brand.mjs --check`, which CI runs to warn when the copy is behind

## Changing the logo or icons

Change `scripts/generate-assets.mjs`, run `npm run generate`, merge, then copy the files into each
app (and its inline wordmark component) and bump the icons' `?v=` cache-busting query there.

## Changing a brand value

1. Change `tokens.json` here and merge (`node scripts/check.mjs` validates it).
2. In each of new-website, apply and portal: run `node scripts/sync-brand.mjs`, update the
   stylesheet until the brand test passes, and open a PR.

Check contrast before changing a text colour: portal and apply run axe (WCAG 2.1 AA) in e2e.
